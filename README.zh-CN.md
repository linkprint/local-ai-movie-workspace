> **先用掉团队本来就在付费的 AI Plan，不要再重复支付图片 API 费。** 以 5 名原本就拥有 ChatGPT Pro 20x 的成员、每月完成 10,000 张背景设定图和分镜稿图的生成/编辑为例，这套架构可避免约 **410–1,650 美元/月**，即 **4,920–19,800 美元/年** 的 GPT-Image-2 纯输出 API 费用，另可避免编辑图片的输入 Token；这还**没有计算**纯 API CLI 方案中的文字模型、Agent 推理、工具调用和长上下文 Token。更重要的是，每个人都用自己的 ChatGPT 账号登录 CLI：OpenAI 侧的 Codex 活动受该账号及其数据控制管理，本地历史、工程文件和凭证则留在各自隔离的持久 Workspace 中。完整假设、官方现价、Plan 限额和净成本说明见下文。

服务器放在工作室、机房，甚至家里的角落；人在片场、在家、在高铁上，打开浏览器登录，你的工程、你的 AI、你跑到一半的镜头，都在原地等你。

## 写给影视创作者：这不是又一个 AI 网站

（不懂技术？只看这一节就够了。）

如果你做过 AI 影视，这些场景你一定熟悉：剧本在一个聊天窗口里改，概念图在另一个网站抽卡，视频在第三家平台排队，素材散落在网盘、微信和桌面文件夹里。每家平台单独收费、单独限流、单独审核——镜头生成到一半弹出“内容不合规”，可你只是在写一个反派的独白。

Movie AI Workspace 走的是另一条路：**与其在别人的平台上租工位，不如把自己的机器变成片场。** 它是一个开源项目，把一台装了显卡的服务器，变成一整套属于你和你团队的影视创作平台——AI 编剧、图像分镜、视频生成、素材管理，全部在同一个地方、同一个工程里发生。

### 一台服务器，变成一整间片场

- **一间不打烊的编剧室。** AI 帮你拆剧本、改台词、顺场次、做翻译——用的是你自己部署的模型。恐怖、犯罪、战争、亲密关系这些正常影视题材，不会写到一半被拒绝。
- **一张随便试错的分镜台。** 概念图、分镜、风格探索，本地图像模型想迭代多少轮就迭代多少轮，不用数着点数心疼。
- **一个能出镜头的摄影棚。** 通过 MiniMax H3 的固定工作流，文生视频、图生视频、首尾帧、参考生成，成片直接进工程素材库。
- **一个按项目归档的素材库。** 每部片子一个工程：剧本、参考、生成结果、成片都在一起，不再散落四处。

### 几台机器，怎么让全组人都排得开

AI 服务器很贵，你大概率不会人手一台。真正的难题从来不是“买几台”，而是**有限的几台，怎么让全组人都不耽误活**。

大多数团队现在的做法是在群里喊一嗓子：“谁在用 2 号机？”然后就是熟悉的剧情——两个人同时开工把显存挤爆、有人的任务跑到一半被挤掉、有人占着机器出门吃饭、更常见的是没人知道其实有台机器空了一下午。

这套系统把显卡变成像会议室一样可以预约的资源：

- **打开就知道哪台空着。** 按日期查看每台服务器的档期：谁在用、到几点、哪几段没人。看到机器正空着，可以直接“立即开始”进去干活。时间按每个人自己的时区显示，异地协作不用心算时差。
- **约到就是你的，谁也挤不掉。** 同一台机器的同一时段不可能被两个人约走——这由 PostgreSQL 的排他约束在数据库层保证，不是应用层的君子协定。任务跑到一半被人踩掉的事，从机制上就不会发生。
- **不够用可以顺延。** 活没干完、后面那段又恰好没人预约，直接延长档期，不用退出来重排。
- **空转的资源会自动收回。** 工作区闲置到期会自动停止，私有模型的使用授权也随预约到期或爽约自动回收。机器不会因为有人忘了下线，就白白空转一整晚。
- **维护时间提前挡住。** 要升级驱动、换模型、重启服务，设一个维护窗口，那段时间就不接预约。也可以把某台机器设为“排空”：不再接新预约，但让正在跑的活安全跑完。
- **多台机器统一排。** 预约是按具体计算节点来的，这台跑图像、那台跑视频，各排各的，互不干扰。
- **谁用了什么，有账可查。** 关键动作都进审计记录，排片和复盘不用靠回忆和聊天记录。

### 服务器在机房，片场随身走

这套系统从第一天起就是为**远程使用**设计的。机器留在原地，你在哪里都能开工：

- **一个浏览器就够了。** 登录门户、预约档期、打开工程，熟悉的工作台原样出现在眼前——笔记本、平板都行。
- **断开不等于中断。** 合上电脑，服务器继续替你干活；重新登录，回到的还是刚才那个现场，连你和 AI 聊到一半的对话都还在。
- **工作跟着你走，而不是把你拴在机器旁。** 白天在工作室排好的镜头任务，晚上在家打开浏览器验收；出差路上灵感来了，随手连回去改两版台词。

> 下午五点，工作室：看一眼今晚 3 号机没人，约上八点到十一点，让 AI 把第三场的分镜整理成镜头清单，提交两条视频生成任务，合上电脑下班。
> 晚上十点，家里：打开浏览器，两条镜头已经躺在素材库里。挑一条让 AI 对照成片要求检查，顺手把明天的档期也约好。
> 你的电脑合着，服务器没停，片子一直在往前走。

### 顺便告别几件心累的事

- **告别无底洞式的按次扣费。** 改台词、顺场次、翻译、概念图——这些一天几百次的高频操作跑在自己的显卡上，迭代多少轮都不再心疼点数。
- **告别 ComfyUI 调参地狱。** 一套像样的图像流程——带 LoRA、带加速——过去意味着在 HuggingFace 和 Civitai 上翻模型、连节点、对版本，出了错再调试半天。在这里，这些复杂配置让 Codex 照着手册替你搭好，封装成管理员固定的工作流：创作者只管调用，一个节点都不用碰。
- **告别 IP 外泄的隐忧。** 未公开的剧本、世界观设定、选角参考、粗剪，都可以全程留在自己的服务器里，不经过任何第三方平台。
- **告别一刀切的审核。** 规矩依然有，但由制片方自己定：谁能用、什么时候用、能生成什么，都在自己的权限和审批体系里——把通用平台的过滤器，换成适合影视创作的制作规则。

### 说句实在话

这个项目是作者用 5 天业余时间做出来的，粗糙的地方不少：边角没打磨、文档还在长、换一套硬件就得重新对接。它不是一个成熟商品，别指望开箱即用。

但它确实解决了我们自己小团队的真问题——几台 AI 服务器，怎么让全组人有序地用起来：不打架、不空转、人在外面也能开工。如果你的处境和我们相似，它至少是一个已经跑通、可以照着改的起点。

### 我不懂技术，怎么开始？

搭建这套系统需要一位技术伙伴——或者按这个项目自己的推荐方式，让 Codex / Claude 这样的 AI 助手照着仓库里的完整手册来安装。装好之后，创作者每天接触的只有浏览器里的门户和工作台。把下面的技术部分转给负责部署的人，就可以开工了。

---

**以下写给技术伙伴与部署者：预约你自己的 AI 服务器，打开一个可持续接力的 Codex 工作区，把私有模型变成团队都能安全使用的影视创作平台。**

Movie AI Workspace 是为拥有一台或多台 AI 服务器的团队准备的开源控制平台。它把预约门户、隔离工程、持久 AI 计划账号、私有语言模型路由和固定图像/视频工作流组合在一起，同时不把 GPU 宿主机、模型端口或任何 key 暴露给普通用户。

成员预约服务器、选择工程、重新连接同一个 tmux 会话，让 Codex 规划工作，再通过受控的 `movie-ai` CLI 完成 MiniMax H3 视频创作。

## 它解决什么问题

- **不再靠群聊抢 GPU。** 预约窗口由 PostgreSQL 排他约束（`EXCLUDE USING gist` + `tstzrange`）按计算节点强制不重叠，配合维护窗口、节点排空状态和预约状态决定执行权；闲置工作区与到期/爽约的模型授权会被自动回收。
- **使用自己的 AI Plan。** 每个人的 Codex 身份独立持久化，也可以给合规授权的操作人提供管理员托管的公司身份。
- **在 `/model` 中使用私有模型。** Qwen 3.8 27B 与 DeepSeek V4 Flash 的部署别名都经过预约绑定的 Broker。
- **把影视流程做成能力，而不是提示词碎片。** Workspace 镜像携带 H3 提示、生成技能、固定工作流、媒体库和成品验收规则。
- **断线后继续，而不是重新开始。** 浏览器终端、tmux、工程卷和账号卷共同保持工作上下文。
- **从单机稳妥走向多机。** 当前发布实现中心 Portal 和单执行节点；安装手册第 8 章给出增加计算节点的完整流程，多节点数据模型（按节点的排他约束、节点注册与健康检查）也已随代码发布。

## 核心结构

| 层 | 作用 |
| --- | --- |
| Portal | Laravel/Filament 登录、TOTP、预约、工程、后台和媒体库 |
| Workspace | 加固的 Codex 终端、tmux、持久工程和独立账号 |
| Model Router | 保留正常 Codex 路由，只转发获准的私有模型 |
| AI Broker | 校验预约授权，限制语言/图像/视频请求契约 |
| Media Adapter | 连接批准的 MiniMax H3、图像和风格工作流 |
| Host Control | 通过 Unix Socket 执行固定 GPU 预检和服务动作 |
| AI 交接 | `AGENTS.md`、`CLAUDE.md`、管理员技能、手册和测试 |

```text
预约 -> 选择工程 -> 选择个人/公司 AI 身份 -> 进入浏览器 tmux
     -> Codex/Claude 规划 -> 私有文本模型或 movie-ai CLI
     -> 固定 Broker 工作流 -> 工程媒体库中的可验证成品
```

## 模型与创作能力

- Codex 托管模型继续使用进入 Workspace 时选择的 Codex 身份。
- `qwen3.8-27b-uncensored` 是可配置的私有 Qwen 部署别名。
- `deepseek-v4-flash-0731` 是可配置的私有/外部 DeepSeek 部署别名。
- 提供 Z-Image-Turbo 与 Hunyuan 本地图像契约。
- MiniMax H3 通过管理员固定工作流提供 T2VA、I2VA、FL2VA、L2VA 和原生 Ref2VA。

仓库不分发模型权重。“uncensored”只表示操作者自行提供的端点别名；模型许可、安全策略与合法使用由部署者负责。

## 为什么自部署的 uncensored 模型特别适合电影制作

当 Codex 站在你自己的模型和 GPU 前面时，它就不再只是聊天机器人，而是整个制作流程的**生产大脑**：拆解影片、维护计划、加载正确的 Skill、准备镜头、调用图像与 MiniMax H3 工作流，再检查最终文件。同一个终端中，创作者可以通过 `/model` 切换到操作者提供的 `deepseek-v4-flash-0731` uncensored 端点或 `qwen3.8-27b-uncensored`，不用离开工程，也接触不到模型端口和 key。

这套组合对真正的影视工作非常有价值：

- **让编剧室不断线。** 合法的虚构作品经常涉及恐怖、犯罪、战争、政治讽刺、亲密关系、反派对白、身体变形和其他成人主题。由片场自己控制的 uncensored 模型不容易在制作中途突然拒绝、净化语气，或逼着团队反复用隐晦词改写正常的创作意图。
- **让未公开 IP 留在公司内网。** 剧本、世界观设定、选角参考、分镜、粗剪和客户概念都可以留在自己的服务器。成员通过预约绑定的 Broker 使用模型，而不是拿到供应商 key 或裸露的 LAN 地址。
- **像调度剧组成员一样调度模型。** 部署者可以决定权重、量化、上下文长度、系统提示、LoRA、采样参数和升级时间。一个模型负责剧本与连续性，另一个模型负责镜头推理；托管 Codex 继续承担规划、编码、工具调用和团队接力。
- **把大量迭代变成可控产能。** 改一版对白、再跑一轮提示、翻译、镜头变体或连续性检查，不再等同于又一次按 Token 付费和供应商审批。持久工程、tmux、Skill、固定 Workflow、Seed 和成品检查共同保留制作方法。
- **从聊天直接走到成片。** 这不是给模型套一个聊天界面。同一个受控 Session 可以读取工程媒体、调用电影 Skill、提交有边界的 H3 任务，并把验证后的影片送回工程媒体库。

对电影人来说，真正的突破不只是“uncensored 模型愿意回答”，而是同一个私有创作大脑从故事梗概到最终镜头始终连接着同一工程、工具、参考素材、Skill 和人工审批。**Uncensored 不等于无人治理：**这套架构只是把第三方平台的通用过滤器，替换成制片方自己的合法制作规则、权限、预约授权和 Broker 执行边界。

## 用每个人已经购买的 ChatGPT Plan 生成和编辑图片

每个登录者都可以在隔离的 Workspace 中保留自己的 ChatGPT/Codex 身份。当该用户的 Plan 和 Codex 使用界面提供图像工具时，Codex 可以通过用户已有的 Plan 配额调用 `gpt-image-2`，**生成和编辑**背景设定图、环境气氛图、角色设定图和分镜稿图。团队不必在每个 Workspace 中放入同一个 OpenAI API Key，也不必把每一轮视觉迭代都送进单独按量计费的 API 账号。

比省钱更重要的是账号和数据归属：每个 CLI 使用创作者自己的 ChatGPT 登录态，而不是全组共用一个 API 身份。发送给 OpenAI 处理的内容归入该用户自己的 Codex 使用路径，并受该账号的条款与数据控制管理；本地 Codex 历史、工程文件和凭证则保存在该用户独立的持久 Workspace 中。公司 Plan 身份仍然可以作为一个单独、明确授权的选项。OpenAI 也说明，[本地 Workflow 在用户设备上运行，ChatGPT 数据控制适用于 Codex 处理的内容](https://help.openai.com/en/articles/11369540-using-codex-with-chatgpt)。

这不是会计话术。OpenAI 明确说明 [ChatGPT 订阅与 API 分开计费](https://help.openai.com/en/articles/9039756)，本项目不会把订阅额度伪装成 API 余额；它保留每个用户自己的登录态，在对应 Plan 和界面确实提供图像工具时优先走该路径。任何 API 回退仍然按 API 计费，每个账号也仍受当时的 Plan 限额、条款和防滥用规则约束。

**一个透明的 5 人工作室算例（价格核对日期：2026-08-28）：**假设 5 名创作者原本就各自订阅[每月 200 美元的 ChatGPT Pro 20x](https://help.openai.com/en/articles/9793128)，每人每天执行 100 次单图生成或编辑，每月工作 20 天，总量就是 `5 × 100 × 20 = 10,000` 张输出。[GPT-Image-2 官方成本表](https://developers.openai.com/api/docs/guides/image-generation#token-usage-and-costs)中，1536×1024 图片的 Medium 输出价为每张 0.041 美元，High 为每张 0.165 美元：

| 同等工作量全部走 API | 可避免的纯输出 API 费用 |
| --- | ---: |
| 10,000 次 Medium 横图生成/编辑 | **约 410 美元/月**，即 4,920 美元/年 |
| 10,000 次 High 横图生成/编辑 | **约 1,650 美元/月**，即 19,800 美元/年 |

图片编辑还会产生输入图片 Token 和文本输入 Token，因此真实的 API 替代成本可能高于上述纯输出数字。这个估算还故意没有加入文字对话、Agent 推理、工具调用、检索和长工程上下文原本会消耗的 API Token，所以完整避免的 API 账单可能更高。5 个现有订阅合计每月 1,000 美元；因为本算例的前提是团队本来就已购买，所以没有把它重复扣成项目新增成本。如果这些 Plan 是专门为了本系统新购的，计算净节省时必须减去订阅费。“20x”是 Plan 档位，不代表官方保证固定数量的 20 倍图片。实际节省额等于团队现有 Plan 限额内完成的工作量乘以当时的 API 单价。

## 这是一个有明确偏好的参考实现，不是万能安装包

这个项目是作者用 5 天业余时间、围绕自己实际拥有的一组 AI 服务器做出来的，完全源于个人兴趣，也确实先解决了自己小团队的服务器共享问题。它是一套带有可运行契约的工程参考，不是为了适配所有机柜、GPU、虚拟化平台、存储、网络、防火墙、模型服务和公司账号体系而打磨过的商业安装器。

因此，文档优先记录明确、可审计的参考拓扑，而不是假装拥有不存在的通用性。示例中的 systemd 单元、Socket 路径、Compose 网络、节点角色、GPU 状态切换和运维假设，描述的是本项目实际开发所依据的系统；它们**没有针对所有服务器布局优化**。如果你的硬件和网络不同，原样复制命令并不等于完成部署。

想使用本项目时，请让 Codex 参与移植。先要求它完整阅读 `AGENTS.md` 和安装手册，盘点你的真实机器，再逐项建立以下映射：

- Portal、Workspace、Broker、Adapter、Worker 与模型服务器分别部署在哪里；
- GPU 型号、模型运行时、显存切换、存储和持久卷如何安排；
- LAN CIDR、DNS、TLS、防火墙、Unix Socket、SSH Tunnel 与出口策略；
- systemd/Compose 归属、运行用户、Secret、备份和恢复边界；
- 本地模型别名、API 兼容性、上下文上限和验收测试。

可以直接给 Codex 这条起始指令：

```text
完整阅读 AGENTS.md 和 docs/AI_INSTALL_AND_OPERATIONS_GUIDE.md。修改任何文件前，先盘点我的真实服务器。把这套参考架构映射到我的 GPU、网络、存储、模型端点和账号边界；不要盲目照抄示例地址或服务假设。保留安全契约，然后提出最小配置改动和分阶段验收计划。
```

本项目真正可复用的是架构、安全边界和 AI 接手机制，具体部署值只是示例。系统仍然存在粗糙边缘和环境相关工作；最终安装是否适合你的基础设施，需要由部署者自己验证和负责。

## 把这套参考架构变成你自己的内部 AI 平台

可以。本仓库可以根据客户自己的服务器条件，移植成具备同类能力的完整系统：AI 服务器预约网站和管理后台、按用户隔离的 Workspace、工程媒体库、公司 AI Plan 或个人账号的 Codex/Claude Session、本地与外部模型路由，以及 MiniMax H3 制作工作流。Codex 或其他工程代理可以把仓库当作一份可执行的系统规格，不必从零重新发明这些契约。

一套客户化部署可以覆盖完整链路：

- 盘点真实服务器、GPU、显存、网络、存储、模型运行时、账号边界和运维限制；
- 规划并配置 Portal、Gateway、PostgreSQL、Redis、Manager、Router、Broker、Adapter、模型服务和一台或多台 Compute Worker；
- 接入本机模型、OpenAI-compatible 外部端点、ComfyUI 自定义节点、MiniMax H3 和其他经管理员批准的媒体工作流；
- 配置 GPU 预约、节点独立 Secret、模型清单、个人账号、公司 AI Plan、tmux Session、Skill 和 AI 接手文件；
- 建立 DNS、TLS、SMTP、防火墙、出口、备份、恢复和最小权限的服务归属；
- 交付客户专用的 `AGENTS.md`、`CLAUDE.md`、服务器上下文、运维手册和验收测试，让新的 Codex 或 Claude Session 能安全接手。

客户或运维者需要提供准确的硬件与网络清单、计划使用的模型和运行时、域名与身份认证要求、团队与预约规则、存储预期，以及获批的管理员安装方式。API Key 和密码**不需要粘贴到 AI 对话中**；应当在目标服务器上直接生成或安装到被 Git 忽略的 Secret 文件或客户自己的秘密管理系统中。

当前实现主要面向 x86_64 Linux、Docker Compose、systemd、PostgreSQL、Redis 和内网互联的 AI 服务器。ARM、Kubernetes、云 GPU 集群、多个 VLAN、零信任网络、SSO 或不同模型服务器都可以作为移植目标，但需要明确设计，不能只对示例拓扑做批量替换。只有真实用户能够预约合适的 GPU 节点、进入正确隔离的 Workspace、调用选定的本地或外部模型、执行获批的媒体任务并取回验证后的成品，才能算部署完成；容器显示 Healthy 并不等于交付完成。

## 快速开始

安全安装需要少量宿主机配置，因此它不会用一个 `privileged` 容器假装“一键安全”。

```bash
git clone https://github.com/linkprint/local-ai-movie-workspace.git movie-ai
cd movie-ai
sh ops/bootstrap.sh
```

随后编辑被 Git 忽略的 `.env` 与 `env/laravel.env`，安装窄范围 AppArmor、Host Control 和模型 Socket，再启动：

```bash
docker compose build
docker compose --profile workspace-build build movie-workspace-image
docker compose up -d movie-postgres movie-redis
docker compose run --rm --no-deps movie-web php artisan migrate --force
docker compose run --rm --no-deps movie-web php artisan db:seed --force
docker compose up -d
docker compose exec movie-web php artisan movie:create-admin \
  --name="Initial Administrator" --email="admin@example.com" --timezone="UTC"
```

执行最后一条命令前必须配置真实 SMTP。命令只发送一次性密码设置链接，不会创建或通过邮件发送默认明文密码。

迁移包含完整 PostgreSQL 架构；公开 Seeder 只补齐净化后的计算节点模板与公司
Codex 租约单例，不创建用户、预约、项目、会话、任务、审计或媒体记录。

完整步骤见 [AI 安装、运维与交接手册](docs/AI_INSTALL_AND_OPERATIONS_GUIDE.md)。其中包括本机模型、外部 AI 服务器、带 key 的外部供应商桥接、MiniMax H3、Codex/公司账号、tmux、技能发现、备份、测试与开源发布。

## Workspace 技能一定会加载

管理员技能被构建到 Codex 官方管理员技能目录 `/etc/codex/skills`。每次 Workspace 启动都会执行：

```bash
movie-ai skills verify
```

缺少必需 `SKILL.md`、名称不匹配、描述为空或权限可写时，启动直接失败。进入新 Workspace 后用 `/skills` 验收；关键媒体操作使用显式 `$skill-name` 调用。

## 安全边界

安全目标不是一句“自托管所以安全”，而是切实缩小爆炸半径：让创作者完成真实工作，但不把每个浏览器 Session 变成服务器管理员入口。

- **最小权限 Workspace。** 容器使用非特权用户、只读根文件系统、移除 Linux Capability、`no-new-privileges`、tmpfs、seccomp、AppArmor、内部网络和受控出口。`privileged`、`SYS_ADMIN`、`seccomp=unconfined` 等粗暴捷径不属于受支持设计。
- **给能力，不给宿主机 Shell。** Workspace 不能访问 Docker、SSH、systemd、Host Control Socket、LAN 模型端口或任意 ComfyUI Workflow。经过审核的宿主机操作只能走窄范围 Unix Socket 契约；媒体任务只能走受限 `movie-ai` CLI 和 Broker Schema。
- **预约同时也是授权边界。** 短期签名 Grant 绑定用户、工程、计算节点、预约和到期时间；Broker 负责 Job 状态与撤销，PostgreSQL 排他约束阻止所有权重叠。预约到期、爽约、取消或主动放弃都会撤销对应模型授权。
- **创作 Session 不携带供应商 Key。** Provider 凭证留在 root 可读 Secret、Secret Manager 或管理员控制的 Adapter 中；模型通过固定 Socket 进入 Broker，Workspace 只获得预约范围 API，不需要复制共享 Key。
- **账号和工程相互隔离。** 个人与公司 AI 身份使用不同卷，每个用户和工程分别持久化状态与媒体。协作不需要复制账号凭证，也不需要共享其他成员的 CLI 历史。
- **真实拓扑留在控制面之后。** 用户 API 不返回节点 IP、内部 Broker URL、内部健康细节或 HMAC Secret；受控 Egress 也降低失陷 Workspace 被当作内网跳板的价值。
- **认证与可追溯性。** Portal 支持角色与 TOTP；关键预约、管理和 Runtime 操作会留下可复核记录。
- **开源发布也有安全 Gate。** Git 中不能出现 Provider Key、私钥、密码、`auth.json`、用户媒体、生产数据库记录或数据库导出；公开版本只包含完整 Migration、净化后的初始化数据，并在发布前自动扫描当前树和历史。

这是一套带自动化安全 Gate 的安全导向参考架构，不代表已经取得正式安全认证或通过独立渗透测试。Docker 宿主机与管理员仍是最终信任锚；部署者必须在真实基础设施上验证 TLS、防火墙与出口策略、Secret 轮换、补丁、备份、恢复和外部模型供应商的数据处理方式。

## 当前发布边界

中心 Portal 和单执行节点链路已经实现。多节点所需的数据库字段、节点注册与健康检查已随代码发布，增加计算节点的步骤见安装手册第 8 章；但 Worker 路由与故障 Gate 尚未完成真实多机验收，在此之前不宣称生产多节点可用。
